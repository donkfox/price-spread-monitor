# 拼多多 -> 得物同码预计利润监控

## 桌面软件

打开桌面管理软件：

```powershell
.\open-app.ps1
```

桌面软件提供四个页面：

- **运行总览**：彩色显示后台状态、今日扫描轮次、今日报警、本月已实现利润和实时日志；
- **报警中心**：直接查看货号、同规格成本、最近成交、预计收入和利润，可搜索、多选删除旧报警、加入记账或下载 Excel；
- **订单记账**：可从报警一键添加，也可手动填写货号、规格、成本、运费和到手价；支持一键切换未到货、已到货、已售出和已退货状态，并按月显示商品总价、运费、流水、预计利润与已实现利润；
- **部署与设置**：检测 MuMu、ADB、拼多多、得物、后台任务和 ntfy，可一键初始化并修改利润阈值、扫描间隔和 ntfy 私密主题。

软件绝不会设置开机自动检测。每次电脑开机后需要手动打开软件并点击“开启监控”。关闭桌面窗口不会停止本次扫描和 ntfy 通知；需要结束时点击软件顶部的“停止监控”。

## 桌面机器人

小帮机器人已独立为单独项目，位于 `D:\workspace\小帮机器人`。从这里运行：

```powershell
cd D:\workspace\小帮机器人
.\open-robot.ps1
```

机器人身份与记忆保存在 `小帮机器人/runtime/robot.sqlite3` 并自动备份，不再与本项目共享运行数据。

构建可发给其他 Windows 用户的发布包：

```powershell
.\build-release.ps1
```

发布文件生成在 `release\PriceMonitorCenter-Windows.zip`。发布包包含桌面程序 `PriceMonitorCenter.exe`、无窗口后台服务 `PriceMonitorService.exe` 和 ADB platform-tools，不包含本机运行记录、账号信息或 `secrets` 私密通知密钥。新用户仍需安装 MuMu、安装并登录拼多多和得物，然后在软件的“部署与设置”页面运行一键初始化。

该项目通过 MuMu 的 ADB 控制已登录的拼多多和得物 App，自动从拼多多推荐流发现商品，并只在以下条件全部满足时报警：

- 两个平台详情中的货号完全相同；
- 两个平台存在相同且可售的规格；鞋类规格必须是相同数字鞋码，其他商品可以是颜色、容量、服装码或套装；
- 得物该规格存在最近成交记录；
- 程序把该规格最近成交价填入得物出价页，并读取平台计算的预计收入；
- 同规格最近成交不超过 7 天；超过 7 天时，只有该成交价比拼多多详情实价至少高 300 元才继续试算；
- `得物预计收入 - 拼多多同规格详情实际价格 >= 30 元`。

同一商品如果有多个规格同时满足条件，每个规格都会单独通知并在 Excel 中各写一行，不只保留利润最高的规格。

达到报警条件后，程序会立即发送 Windows 弹窗和已启用的手机通知。手机消息包含品类、货号、匹配规格、拼多多详情实际价格、得物最近成交价、预计收入和预计利润。发送失败会自动重试且不会中断扫描；相同价格组合的重复机会不会重复推送。

它不会绕过验证码或风控，不会提交订单。检测到验证页时会停止当前监控并记录原因。

## 运行

两个 App 需要保持登录状态。监控器在 ADB 不可用时会通过 MuMu CLI 自动启动模拟器。

```powershell
cd D:\workspace\价差监控
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python monitor_service.py --once
```

持续监控：

```powershell
.\run-monitor.ps1
```

桌面的“开启监控”只启动当前 Windows 会话，不创建计划任务或开机启动项；“停止监控”会结束检测，并自动清理旧版本遗留的开机任务。

配置位于 `config.json`。默认每 1 分钟扫描一轮，每轮在刷新首页前实际打开核验最多 4 个带货号候选；当前区域候选不足时会继续向下浏览，最多查看 4 个推荐区域。被判定为重复、无货、无可靠货号或真实多货号的商品允许跳过。拼多多列表价格只用于发现候选和控制重复打开，绝不参与利润计算；每个参与比较的价格都来自进入详情后逐个选择规格所显示的实际购买价。

PushDeer 官方安卓客户端已停止服务，因此该通道已关闭。ntfy 私密主题保存在 `secrets/ntfy_topic.txt`；安卓端需订阅同一主题，并允许通知、后台运行和自启动。推荐使用 ntfy 的 F-Droid 版本维持实时后台连接。

每轮拼多多扫描完成后，程序会记录当前商品并回到首页刷新。只有推荐商品发生变化才算成功；下拉无变化时会切换分类重试，仍无变化则重新载入拼多多页面。

程序按商品流水处理：拼多多核验一个商品后立即去得物核验，完成后返回原推荐位置看下一个。每轮实际尝试 4 个候选后刷新拼多多首页；候选不足或被规则排除时可以提前刷新。

得物不会使用主页搜索。程序固定进入“我 → 出售 → 我要出售”，搜索货号后进入出售商品页，严格核对页面展示的货号，并读取可售规格及最近出售记录。规格列表会自动向下滚动，避免底部工具栏遮住后续规格。无法严格核验的商品不会永久丢弃，而是在 5 分钟后重新尝试。

每个规格只使用得物展示的最新一笔成交。最新成交在 7 天内时正常试算；超过 7 天或成交时间无法识别时默认作废，除非“该笔成交价 - 拼多多同规格详情实价”达到 300 元。即使触发旧成交例外，最终仍必须以得物页面计算出的预计收入减去拼多多成本达到 30 元才报警。

部分商品进入报价前会出现“请确认实物是否一致”。程序会先核对该页的主货号和版本，确认一致后自动点击“是这款”，再在最终出售页复核一次货号。核验时会逐个选择与拼多多相同且有最近成交记录的规格，进入出价表单填入该规格最近成交价，并再次读取输入框校验；输入不完整时放弃该规格。预计收入为零或负数属于有效计算结果，会照实记录但通常不会达到报警条件。程序只读取“预计最高收入”后立即返回，不会点击“扫码确认”“支付保证金”或最终提交出价。

商品识别支持常见货号、产品型号和 8 至 14 位商品条码。`250ml`、`1000g`、`245mm`、`30x40x20` 等容量、重量和尺寸规格不会被当成货号。拼多多详情只有一个唯一型号时，规格按钮无需重复显示该型号；一旦发现多个竞争型号，仍会拒绝报警以避免串款。

得物候选按屏幕从上到下、从左到右排序。出售商品页必须显示与目标一致的货号；货号仅相差连字符格式时视为相同，例如 `211702100` 与 `211702-100`。定制、收藏版、典藏版、礼盒、联名、限定、球员版、复刻以及高帮/中帮/低帮等互斥版本必须与拼多多标题一致，否则不参与价差计算。

鞋类只比较两平台完全相同的数字鞋码。颜色、容量、服装码和套装等非鞋类规格会标准化后严格匹配。程序不再退化为 `ONE` 或拼多多标题价格；规格不同、同规格没有最近成交记录、输入值校验失败或无法读取有效预计收入时都不会报警。

每次开启检测都会在 `D:\价差报警记录` 新建一个以启动时间命名的 Excel 工作簿。工作表只记录报警商品，每条报警占一行，包含报警时间、货物品类、货号、匹配规格、拼多多详情规格价、得物同规格最近成交价、得物预计收入、预计利润、最近成交记录和购买方式。

监控运行时不要长期打开正在写入的报警工作簿。如果文件被 Excel 占用，程序会自动创建带 `_续写2` 后缀的新工作簿并继续保存，不会中断扫描或丢失本次报警。

## 输出

- `runtime/monitor.log`：运行日志
- `runtime/monitor.sqlite3`：扫描、拒绝原因和报警记录
- `runtime/alerts.jsonl`：只包含预计利润大于等于 30 元的机会

预计收入由得物在输入最近成交价后实时计算，已经反映页面当时展示的费用；平台规则、优惠资格、运费和费率仍可能变化，购买前需要人工复核。程序不会代下单，也不会提交得物出价。
